# Guía de Contribución

Gracias por tu interés en contribuir a **Engineering Platform**.

## Flujo de trabajo

1. Crea una rama a partir de `dev`: `feature/nombre-descriptivo` o `fix/nombre-descriptivo`.
2. Realiza tus cambios siguiendo los [estándares de código](docs/standards/coding-guidelines.md).
3. Abre un Pull Request hacia `dev` con una descripción clara del cambio.
4. Espera al menos una aprobación antes de hacer merge.

## Convenciones de commits

Usamos el formato [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` nueva funcionalidad
- `fix:` corrección de errores
- `docs:` cambios en documentación
- `refactor:` cambios internos sin alterar el comportamiento
- `test:` agregar o modificar pruebas
- `chore:` tareas de mantenimiento

## Revisión de código

Todo cambio debe cumplir con:

- Cobertura mínima de pruebas.
- Cumplimiento de las [guías de seguridad](docs/standards/security-guidelines.md).
- Revisión de al menos un miembro del equipo.

## Código de conducta

Sé respetuoso, colaborativo y constructivo en cada interacción del equipo.
